1. Le processeur

Comment une suite d'instructions devient-elle des opérations exécutées ?

CPU (Central Processing Unit)Circuit intégré qui exécute des instructions codées en binaire (additionner, charger, comparer, sauter).
Programme
Suite d'instructions.
ISA
Instructions, registres, modes d'adressage, modèle mémoire visibles par le logiciel.
Microarchitecture
Implémentation concrète : pipeline, caches, unités d'exécution, prédiction de branchement.
À retenirDeux CPU x86-64 exécutent les mêmes programmes (même ISA) mais peuvent avoir des performances très différentes (microarchitecture différente).

Le cycle d'instruction

Exemple : ADD R1, R2, R3 = R1 ← R2 + R3. Le CPU lit le codage, décode ADD et les 3 registres, lit R2 et R3, envoie à l'UAL, écrit la somme dans R1, passe à l'instruction suivante. Sans mise à jour du PC, le CPU referait la même instruction indéfiniment.

Incrémentation du compteur ordinal (PC)À chaque instruction, PC ← PC + taille de l'instruction en octets (la mémoire est adressée octet par octet). Instructions de 32 bits = 4 octets : PC = 0, 4, 8, 12… Un saut (BEQ, BNE…) remplace PC par l'adresse cible. Avec des instructions de longueur variable (x86), l'incrément dépend de chaque instruction.

Pipeline et branchements

Débit ≠ latenceLe pipeline augmente le débit d'instructions, pas la vitesse d'une instruction isolée. Dépendances, accès mémoire et branchements créent des arrêts. Le prédicteur de branchement devine le chemin ; une mauvaise prédiction annule les instructions déjà engagées.

CISC et RISC

CISCRISC
IdéeInstructions nombreuses, parfois complexes, longueur variableInstructions régulières, opérations élémentaires
Exemplesx86 / x86-64ARM, RISC-V
IntentionDensité du code, compatibilité historiqueDécodage simple, efficacité, extensibilité

RISC ne garantit pas « 1 instruction = 1 cycle » : c'est une intention de conception.

Cœurs, threads, histoire

  • Cœur : unité exécutant un flux d'instructions. Multicœur : plusieurs cœurs sur une puce ; le gain dépend du parallélisme du programme.
  • SMT : un cœur gère plusieurs threads logiques (ressources partagées) : 2 threads logiques ≠ 2 cœurs physiques.
  • SoC : CPU, GPU, contrôleurs (et NPU) dans une même puce.

2. Architecture interne et langage assembleur

Chapitre 2 : de von Neumann au langage machine.

UAL
Traite les opérations arithmétiques (entiers) et booléennes.
UC (unité de contrôle)
Circuit logique séquentiel : séquence les commandes, interprète et exécute les instructions.
Registres
Mémoire interne la plus rapide, mais la plus chère (place limitée). Ex. : 16 registres de 8, 16, 32 ou 64 bits (souvent la taille d'un bus).
Adresse et busAdresse = nombre désignant un endroit précis de la mémoire. Bus = nappes de fils transportant l'information.

Langage machine

Suite de bits interprétée par le processeur : son seul langage natif. Une instruction machine = champ code opération + champ opérande. Exemple (addition de 2 et 3) : 10111000 00000010 00000101 00000011. Instructions de bas niveau : arithmétiques, transfert de données (registre ↔ RAM), logiques, sauts et branchements. Programmer directement en binaire est extrêmement difficile, d'où l'assembleur.

Assembleur

Représentation textuelle du langage machine : chaque combinaison de bits est un mnémonique. Exemple : « additionner 125 et R2, ranger dans R1 » = ADD R1,R2,#125 (le symbole # indique une valeur immédiate) = 11100010100000100001000001111101 en machine.

3. Les mémoires

Accéder vite, conserver temporairement, sauvegarder durablement.

Une mémoire est un tableau de cases : chaque adresse désigne une case qui contient une donnée. Écrire remplace le contenu ; lire le restitue (sans le détruire en RAM). Aucune technologie n'offre à la fois vitesse, grande capacité, faible coût et non-volatilité : d'où la hiérarchie.

Vitesse / densitéTrès rapide / faibleRapide / élevée
UsageCaches L1-L3Mémoire principale

Non volatile : ROM, Flash, stockage

Ne pas confondre« Non volatile » = conserve hors tension. « Lecture seule » = écriture limitée. La Flash est non volatile et réinscriptible. HDD = plateaux magnétiques ; SSD = Flash NAND. Un support n'est pas une sauvegarde.

Le cache

Petite SRAM entre CPU et RAM. Il exploite la localité temporelle (donnée récente → réutilisée) et spatiale (adresses proches → demandées ensemble). Hit : donnée trouvée ; miss : il faut descendre d'un niveau. Plusieurs cœurs avec chacun une copie : les protocoles de cohérence évitent de lire une valeur périmée (coût en trafic et latence).

Unités

1 octet (B) = 8 bits. Décimal : 1 kB = 1 000 B. Binaire : 1 KiB = 1 024 B, 1 MiB = 1 024² B. D'où l'écart entre capacité annoncée et affichée.

Mémoires : approfondissement

Chapitre 3 : accès, capacité, cache.

Vue interne et capacité

Mémoire = mots de k bits, chacun avec une adresse sur n bits : 2ⁿ adresses (de 0 à 2ⁿ−1). Supports : semi-conducteur (registre), magnétique, optique, Flash. Emplacement : dans le processeur (registres), dans le boîtier de l'UC (mémoire principale), à l'extérieur (secondaire).

Taille max = 2A cases (A = largeur du bus d'adresses)
Capacité = taille × taille d'une case (en octets)

Performance : temps d'accès (de la demande à la fin de l'opération) et débit (Mo/s). Le temps d'accès augmente avec la capacité, d'où la hiérarchie : seules les données les plus utilisées doivent être très rapides à lire.

Modes d'accès

ModePrincipeUsageTemps d'accès
SéquentielLire les données précédentes pour atteindre la voulueArchivage de gros volumesVariable
AléatoireChaque mot a une adresse unique, n'importe laquelle accessibleMémoire principale, certains cachesConstant
DirectDécodeurs vers le bloc, puis déplacement dans le blocDisquesVariable

Exemple séquentiel (100 cases, pointeur à 0) : adresse 60 = 60−0+1 = 61 tests ; puis adresse 40 = (99−60+1) + (40−0+1) = 81 tests.

Cellule et circuit RAM

Une cellule a 3 connexions : entrée de sélection, entrée de contrôle (lecture ou écriture) et ligne de données bidirectionnelle. Pour M mots de B bits : log₂(M) lignes d'adresse et B lignes de données. DRAM : 1 transistor + 1 condensateur ; SRAM : 6 transistors.

Le cache en détail

Les processeurs progressent d'environ 55 % par an, les mémoires d'environ 7 % : le cache comble l'écart. La mémoire est découpée en blocs de mots contigus. En cas de défaut (miss), le bloc est amené de la mémoire principale dans le cache, puis au processeur. Souvent, un cache d'instructions est séparé du cache de données (exécution en parallèle). L1 : sur la puce du CPU, petit et très rapide. L2 : plus grand et moins rapide, il doit être 10 à 100 fois plus gros que L1 pour être intéressant (selon le cours).

Correspondance : adresse MP → adresse cache

TypePrincipeAvantagesInconvénients
Directe@cache = @MP mod (taille du cache). Le reste de l'adresse = étiquetteCalcul simple, étiquette partiellePlusieurs adresses MP pour une même case : écrase même s'il reste de la place
Totalement associativeToute adresse MP peut aller dans n'importe quelle case ; étiquette = adresse complètePlace utilisée dès qu'elle existeAdresse complète à stocker, gaspillage

Exemple (directe) : @MP = 16, cache de 8 cases → 16 mod 8 = 0. En binaire : adresse MP sur 5 bits 01000, cache de 8 cases = log₂(8) = 3 bits → index 000, le reste 01 est l'étiquette. Chaque ligne du cache a un bit de validité, l'étiquette et la donnée.

Performance du cache

Tamm = Ts + te × pe  ;  te = Nd / Na

Ts = temps de succès, te = taux d'échec, pe = pénalité d'échec, Nd = nombre de défauts, Na = nombre d'accès.

Exemple : pénalité 10 cycles, instruction de 2 cycles sans accès mémoire, 1,33 référence mémoire par instruction, taux d'échec 2 % : avec cache = (2 + 0,02 × 1,33 × 10) Tc = 2,27 Tc ; sans cache = (2 + 1,33 × 10) Tc = 15,3 Tc.

Remplacement et écriture

  • Remplacement : aléatoire, FIFO (le plus ancien), LRU (le moins récemment utilisé), LFU (le moins fréquemment utilisé). LRU et LFU sont les plus efficaces ; aléatoire et FIFO plus faciles à implanter.
  • Écriture, bloc présent dans le cache : écrire dans le cache et la mémoire simultanément, ou dans le cache seulement et différer l'écriture mémoire.
  • Écriture, bloc absent : charger le bloc dans le cache puis écrire, ou écrire directement en mémoire.

4. Les bus et interconnexions

Comment l'information circule-t-elle entre composants ?

BusEnsemble de lignes électriques ou de liaisons logiques qui transfère des informations entre composants.

Lecture mémoire : le CPU place l'adresse → le signal de lecture est activé → la mémoire place la valeur sur le bus de données → le CPU la range dans un registre.

Débit théorique

Débit (octets/s) ≈ fréquence (transferts/s) × largeur (bits) ÷ 8

Exemple : 64 bits à 100 MHz = 100 000 000 × 64 ÷ 8 = 800 MB/s. Le débit réel est plus bas (en-têtes, pauses, partage, retransmissions).

NuancePCIe est appelé « bus » mais c'est une interconnexion série par paquets, point-à-point et commutée.

5. Les processeurs graphiques

Milliers de calculs similaires vs quelques flux complexes.

GPUProcesseur spécialisé dans le traitement parallèle (rendu 3D à l'origine, aujourd'hui aussi IA, images, simulations : GPGPU).
  • Le CPU lance un kernel ; le GPU exécute de nombreux threads en blocs (mémoire partagée par bloc).
  • Warps / waves : groupes de threads exécutant la même instruction. Divergence : branches différentes → chemins exécutés l'un après l'autre.
  • Exemple C[i] = A[i] + B[i] : un thread par indice i, idéal car éléments indépendants.
  • Pipeline graphique : sommets → vertex shader → rastérisation → fragment shader → pixels.
  • Mémoire GPU : registres, partagée, cache, globale/vidéo (grande bande passante, latence forte), hôte (transferts CPU-GPU coûteux).
CPU préférableCalcul séquentiel, beaucoup de branches différentes, peu de données, échanges fréquents avec le CPU.

6. Formules à connaître

Temps CPU ≈ nb d'instructions × CPI × durée d'un cycle
Instructions/s ≈ fréquence × IPC (IPC = 1 / CPI)
Débit bus (octets/s) ≈ fréquence × largeur ÷ 8

Exemple : 1,2×10⁹ instructions, CPI 1,5, 3 GHz → 1,2×10⁹ × 1,5 ÷ 3×10⁹ = 0,6 s (idéal ; réel plus long : défauts de cache, RAM, interruptions, branchements).

Exemple : bus 32 bits à 50 MHz → 50 000 000 × 32 ÷ 8 = 200 MB/s.

Fréquence seule ne suffit pas à comparer deux CPU. TDP = enveloppe thermique de conception, pas la consommation maximale.

8. Auto-test

Réponds dans ta tête, puis ouvre.

Pourquoi le compteur ordinal est-il indispensable ?Il donne l'adresse de la prochaine instruction ; sans mise à jour, le CPU répéterait la même instruction.
Le pipeline rend-il chaque instruction plus rapide ?Non : il augmente le débit (latence inchangée voire arrêts).
Pourquoi pas un ordinateur tout en SRAM ?Trop chère par bit et peu dense : on ne peut pas avoir grande capacité à bas coût.
Quel bus indique la destination ? la valeur ? la lecture ?Adresses ; données ; contrôle.
RAM éteinte puis rallumée : pourquoi le document non sauvegardé disparaît ?RAM volatile ; le SSD (Flash) est non volatile.
Pourquoi un processeur rapide peut rester lent ?Il attend des données : mémoire ou interconnexion goulot d'étranglement.
Que fait BEQ 78 après CMP R0,#23 ?Saute à l’adresse 78 si R0 vaut 23.
Cache direct : @MP = 16, cache de 8 cases ?16 mod 8 = 0 : case 0 du cache.
Temps moyen d’une instruction avec cache (2 cycles, 1,33 réf., 2 %, pénalité 10) ?2,27 Tc contre 15,3 Tc sans cache.
Pourquoi un NVMe est plus rapide qu'un SSD SATA ?Il passe directement en PCIe (chemin plus direct, plus de lanes et de parallélisme).
Deux avantages du série point-à-point ?Synchronisation simple à haute fréquence, moins d'interférences, évolutivité par lanes.
